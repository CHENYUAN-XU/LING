# 实时视频陪伴独立项目计划

本文档用于把“类似豆包视频功能”的实时视频陪伴能力从 Project Mnemosyne 主项目中拆出。主项目继续负责人格、记忆、聊天、表达、授权和最终接入；新项目专注摄像头实时感知、语音通话、视觉理解和低延迟互动。

重要声明：本项目计划已由项目作者拿到外部独立制作，并已放在 `E:\视觉\video-companion`。Project Mnemosyne 仓库后续接力开发时必须默认跳过该项目，不在主项目内继续实现视频通话、连续摄像头帧理解、视觉模型抽帧链路或视频会话状态机。本文档保留不删，只作为外部项目计划、接口契约和接回主项目的参考；主项目只通过 `app/video_companion.py` 和 `/api/video-companion/*` 调用外部服务。

## 拆分结论

| 项目 | 负责范围 | 不负责范围 |
| --- | --- | --- |
| LING 主项目 | 单一 companion 资料、长期记忆、文字会话、表达标签、普通文字回复朗读、Live2D/Presence 接入、外部能力授权和最终 UI 入口 | 实时视频理解、连续摄像头帧分析、麦克风/ASR、可打断语音通话链路、视觉模型成本调度、视频会话状态机 |
| Video Companion 独立项目 | 摄像头采集、麦克风输入、实时抽帧、视觉理解、语音识别、低延迟语音回复、通话状态、视频会话安全边界、与主项目的 API/SDK 对接 | 长期人格生成、记忆数据库主权、核心聊天产品、用户账号体系 |

## 产品目标

| 目标 | 说明 | 验收方式 |
| --- | --- | --- |
| 实时视频对话 | 用户打开摄像头后，AI 能基于画面、语音和上下文回应 | 本机浏览器可进行 3 分钟连续会话，无明显断流 |
| 低延迟语音互动 | 支持边说边听，回复尽量短且可打断 | 从用户说完到开始播放回复，常规场景小于 2 秒 |
| 视觉理解 | AI 能识别用户是否在镜头前、表情/动作大意、展示物品或屏幕中的简单信息 | 用固定测试场景验证“有人/无人、举手、展示物品、情绪粗略状态”等结果 |
| 人格接入 | 回复沿用主项目的人格、关系、说话方式和近期记忆 | 同一人格在文字聊天与视频通话中的风格一致 |
| 隐私可控 | 摄像头、麦克风、外部模型上传必须显式授权 | 关闭授权后无法继续采集；日志不保存原始帧和原始音频 |
| 成本可控 | 视觉模型按抽帧频率、画质和场景触发，不无脑逐帧上传 | 有每分钟成本估算、限额和降级策略 |

## 阶段计划

| 阶段 | 名称 | 要做什么 | 输出物 | 完成标准 |
| --- | --- | --- | --- | --- |
| V0 | 技术预研 | 确定浏览器 WebRTC/getUserMedia、后端流媒体、视觉模型、ASR、TTS、主项目对接方式 | 技术选型记录、最小 demo | 能在本机打开摄像头和麦克风，确认可行链路 |
| V1 | 本地视频会话壳 | 独立项目启动页面，摄像头预览、麦克风权限、会话开始/结束、状态展示 | 可运行的本地视频会话页面 | 用户能打开/关闭摄像头和麦克风，不保存媒体 |
| V2 | 抽帧与本地感知 | 定时抽帧，做人脸/人在镜头前/简单动作检测，形成结构化观察 | `VideoObservation` 数据结构和本地检测结果 | 不调用外部模型也能知道“有人/无人/镜头不可用” |
| V3 | 视觉模型接口 | 接入一个可替换的视觉模型 provider，默认关闭上传；支持低频抽帧和按需分析 | `VisionProvider` 接口、成本限流、错误处理 | 明确授权后能对单帧生成自然语言观察 |
| V4 | 语音输入输出 | 接入 ASR 和 TTS，支持用户语音输入、AI 语音回复、可打断播放 | `SpeechSession`、浏览器播放与打断 | 可以不用键盘完成一轮语音问答 |
| V5 | 多模态对话循环 | 合并语音文本、视觉观察、主项目人格上下文，生成短回复 | `VideoTurn` 会话状态机 | 画面变化会影响回复，不再只是普通文字聊天 |
| V6 | 主项目桥接 | 从 Mnemosyne 拉取人格摘要、近期记忆、关系状态；回写通话摘要和重要观察 | API/SDK、鉴权、回写策略 | 主项目中能从人格资料页进入视频会话 |
| V7 | 成本和隐私硬化 | 加入额度、频率、帧质量、敏感场景屏蔽、日志脱敏、用户可撤销授权 | 配置项、管理面板、审计日志 | 外部上传可解释、可关闭、可限额、可追踪 |
| V8 | 体验打磨 | 通话 UI、延迟优化、断线恢复、移动端适配、Live2D/形象联动 | 体验验收清单 | 可以稳定给作者日常试用 |

## 推荐技术边界

| 模块 | 推荐做法 | 原因 |
| --- | --- | --- |
| 摄像头采集 | 前端 `getUserMedia` 采集，默认只本机预览；需要分析时才抽帧发送 | 浏览器权限清晰，用户可直接看到摄像头状态 |
| 视频传输 | V1-V3 用 HTTP/WebSocket 抽帧；需要双向实时音视频后再考虑 WebRTC | 先降低复杂度，避免一开始陷进实时通信工程 |
| 本地检测 | OpenCV/MediaPipe 做人脸、人体关键点、基础表情/姿态 | 便宜、快、隐私更好，可作为视觉模型前置过滤 |
| 视觉模型 | 抽象成 provider，不绑定一家模型；默认关闭外部上传 | 方便以后换模型和控制费用 |
| 语音识别 | 先接一个云端 ASR 或本地 Whisper 方案，统一成 `transcript` 事件 | 后续可以按延迟/成本替换 |
| 语音合成 | Video Companion 自己选择 OpenAI TTS、ElevenLabs 或本地高质量 provider，并支持短句、流式或可打断播放 | 主项目的文字回复朗读不承担实时视频会话状态机 |
| 主项目对接 | 独立服务通过 API 拉取人格上下文，回写会话摘要，不直接写主库 | 降低耦合，避免视频项目破坏主项目核心数据 |

## 与主项目的接口契约

### 主项目提供给视频项目

| 接口 | 用途 | 关键字段 |
| --- | --- | --- |
| `GET /api/video/session-context?persona_id=...` | 获取视频会话启动上下文 | 用户授权状态、人格公开资料、说话方式、关系状态、最近对话摘要、重要边界 |
| `POST /api/video/session-summary` | 视频会话结束后回写摘要 | `persona_id`、开始/结束时间、用户主动透露的重要事实、需要记忆的内容、风险标记 |
| `POST /api/video/observation` | 按需回写重要视觉观察 | 观察文本、置信度、是否允许进入长期记忆、证据类型 |
| `POST /api/video/consent` | 同步用户视频授权 | 摄像头、麦克风、外部视觉模型上传、保存摘要、保存重要观察 |

### 视频项目输出给主项目

| 数据结构 | 用途 | 示例 |
| --- | --- | --- |
| `VideoObservation` | 当前画面观察 | `user_present=true`、`rough_mood=focused`、`object_hint=book` |
| `VideoTurn` | 一轮多模态对话 | 用户语音文本、视觉观察、AI 回复、播放状态 |
| `VideoSessionSummary` | 会话结束摘要 | “用户展示了新买的手账本，说明最近想整理计划。” |
| `VideoConsentState` | 授权状态 | 摄像头开、麦克风开、外部视觉模型上传关 |

## 隐私和成本规则

| 规则 | 要求 |
| --- | --- |
| 默认关闭 | 摄像头、麦克风、外部视觉模型上传都必须默认关闭 |
| 明确授权 | 用户必须分别开启摄像头、麦克风、外部模型分析，不能用一个总开关糊过去 |
| 不保存原始媒体 | 默认不保存原始视频帧、原始音频和截图；只保存用户允许的摘要或结构化观察 |
| 可见状态 | UI 必须持续显示摄像头/麦克风/外部分析是否开启 |
| 可中断 | 用户随时关闭会话后，采集、上传、播放都必须停止 |
| 成本限额 | 必须有每分钟抽帧上限、每小时费用上限和降级策略 |
| 失败明示 | 摄像头不可用、模型额度不足、网络失败要告诉用户原因，不静默失败 |

## 主项目暂时保留的接入点

| 文件/模块 | 保留原因 | 后续处理 |
| --- | --- | --- |
| `app/camera_perception.py` | 现有本机摄像头状态、一次性检查、MJPEG 预览可作为桥接参考 | 不继续扩展成完整视频理解引擎 |
| `app/screen_perception.py` | 保留授权、窗口标题和截图元数据边界 | OCR/截图理解另行规划 |
| `app/user_consent.py` | 主项目仍负责最终用户授权记录 | 后续增加视频项目授权同步字段 |

| `config.yaml` 的 camera/screen/proactive | 默认关闭，作为本机能力和桥接配置 | 不代表视频项目已完成 |

## 先不要做的事

| 暂缓项 | 原因 |
| --- | --- |
| 一开始就做完整 WebRTC | 工程量大，调试成本高；先用抽帧和语音事件验证产品闭环 |
| 默认把每帧上传给视觉模型 | 费用高、隐私风险高、延迟也不可控 |
| 直接写主项目数据库 | 容易破坏主项目记忆和审计边界 |
| 让视频项目自己决定长期记忆 | 长期记忆主权仍在 Mnemosyne，视频项目只提交候选摘要 |
| 把 Live2D、VTube Studio、真人摄像头、AI 视频理解混成一个模块 | 它们是不同层：形象驱动、真人视频、视觉理解、语音通话应解耦 |
